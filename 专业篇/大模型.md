## 一、决定做不做

方向还没定，可以从应用和工程岗各挑一份，先核职责、投递门槛和你已有的项目。再用下面两晚试试任务本身，免得按一个热门词补完三个月课，才发现你不喜欢那类工作。

### 1. 花两个晚上试一遍你可能每天做的事

找一份带公开许可的开源工具手册，写十几道能找到原文的问题。加两道手册里压根查不到的，试着用关键词检索和现成语义检索器找答案。第一晚跑通，第二晚逐条看错在哪里。关键词能搜到报错编号吗？把名字改成日常说法后还能搜到吗？旧版手册是不是把最新版的答案挤出去了？

这项练习可以在普通电脑上做。最后留下两列预测结果和一页错误记录。你可能发现自己喜欢追读原文、判断错误类型，也可能更想弄明白为什么十个人同时问就变慢。选方向时，回想你自愿在什么地方多花了半小时。两晚平时怎么安排，往后大概也是这么安排。

最早需要的基本功是能用 Python 和 Git，能重复同一实验，能把结果解释给别人。对服务系统感兴趣，再拿一个能运行的服务练 Linux、并发和性能测量。

### 2. 顺着自己愿意追的问题找入口

| 想解决什么 | 可以从哪切入 | 需要先核实什么 |
| --- | --- | --- |
| 模型训练与后训练 | 训练关注数据配比、吞吐、优化过程。后训练可比较监督微调、参数高效微调或偏好优化对某项行为的改善。能拿到标注或同一模型稳定试跑资源时，先从一个任务的对照做起。 | 可用模型与数据许可、每次训练成本、可重复次数。偏好优化还需可解释的偏好对和一致的标注规则。 [LoRA 原论文](https://arxiv.org/abs/2106.09685) · [DPO 原论文](https://arxiv.org/abs/2305.18290) |
| 数据与评测 | 比较去重、质量筛选和采样方案，构建覆盖分布变化的评测集，研究自动评分与人工判断在哪些题目上分歧。 | 能否保存出处、数据版本、重复样本处理日志及标注指南。语料里提过同一文档或答案时，评测需查重叠风险。 [FineWeb 原论文](https://arxiv.org/abs/2406.17557) · [HELM 原论文](https://arxiv.org/abs/2211.09110) |
| 推理与服务系统 | 测连续批处理、缓存、量化及调度在真实请求长度和负载下的代价。擅长编程和系统测量时，可以选一个可反复测试的瓶颈。 | 测试时段是否稳定，能否记录日志和显存。若需要跨机器比较，要记录硬件、精度、驱动与软件配置。 [PagedAttention 与 vLLM 论文](https://arxiv.org/abs/2309.06180) · [vLLM 服务压测文档](https://docs.vllm.ai/en/latest/cli/bench/serve/) |
| 检索与应用 | 做检索增强生成（RAG），研究模型在证据缺失、文档改版或多篇证据冲突时怎么答。一个轻量起点是比较关键词检索、向量检索、重排和人工提供证据的表现。 | 文档和用户问题能否合法使用，版本能否冻结，能否标注正确证据和无答案题。 [RAG 原论文](https://arxiv.org/abs/2005.11401) · [BEIR 检索评测](https://arxiv.org/abs/2104.08663) |
| 多模态与交叉方向 | 从有明确错误类型的文档表格、图文定位或公共资料中的图表问答切入。先判断图像提供了什么独有信息，再做纯文本、纯图像及两者合用的比较。 | 图像、转写和题目是否能一起公开或独立复建，标注是否超出能力。跨专业选题尽量找能长期提供指导的领域合作者。 [lmms-eval 维护仓库](https://github.com/EvolvingLMMs-Lab/lmms-eval) |

拿两张纸，各写一个愿意做半年、又能在一个月内做出小结果的问题。写清数据从哪里来，第一段代码要做什么，哪种结果会让你改变判断。模型换了一代以后，你还想追这个问题吗？「文档换版后怎么知道答案过期」「高并发下是哪里在等」都可以用这句话检验。

### 3. 用岗位描述反推硕士阶段要留下什么

拿最近真正想投的职位做一个晚上功课。打开招聘原文，在每条职责后面写一件你能拿出来证明的事。同样写「大模型」，研究岗位可能问有没有控制变量做对照，系统岗位可能顺着压测曲线追问为什么一到某个负载就超时，应用岗位可能更关心系统遇到无证据的问题会不会继续答。两份职位任务差得远，作品也要提前选方向。

「做过某框架」可以展开成一段能讨论的经历，比如「同一批请求下，两种配置的耗时曲线和原始日志在这里」。如果倾向读博，问组里谁读实验方案、谁逐段改稿，再去看硕士生在近期论文里做过哪部分。如果实习是为了转行，提前确认结果在许可下能否展示。 [通用指南中的岗位核查](../高性价比读研指南.md#一要不要读)

可以拿百度 2027 届两条公告练习。AIDU 大模型算法工程师要求相关专业硕士及以上，普通校招的北京大模型算法工程师要求本科及以上，论文和训练经历列为优先项。还有一条推理岗位会问并行计算与批调度。用职位编号和发布日存表，才知道自己算的是哪一道门槛。 [百度 AIDU 校招 J99938](https://talent.baidu.com/jobs/detail/GRADUATE/ab5ec82f-a8be-4b4a-8e6f-5debc34ea804) · [百度北京校招 J100728](https://talent.baidu.com/jobs/detail/GRADUATE/ccfdea4e-4ae4-4954-9062-fd94960a2861) · [百度推理岗位](https://talent.baidu.com/jobs/detail/GRADUATE/7753cdb4-70b0-462b-a634-ee53818c7c9a)

同一家公司的岗位也可以拆开看。小红书 2027 校招有个审核研发岗，介绍的是把 Agent 接进真实审核流程，从原型走到推广。另一个 Agent 平台全栈岗列的是推理部署、服务发布、监控和故障诊断。如果你只有一晚改作品，投前者就挑一个用户做不完的任务，演示改完怎么验证。投后者就补一次实际的服务故障或压测，保留能说明取舍的记录。这两份用作对照，实际投递还要看入口和届别。 [小红书 Agent 应用开发岗](https://job.xiaohongshu.com/campus/position/21969) · [小红书 Agent 平台全栈岗](https://job.xiaohongshu.com/campus/position/22059?referer_code=1HFWERNHLB1B)

再圈出一个能用同一份项目材料的相邻职位，例如从应用研发转看后端，从训练数据转看评测。两边若都要重做作品，就先选你更愿意做的任务。已有能讲的项目，可以[用一周试两条路线](#毕业找工作用一周试两条相邻路线)。

## 二、选择学校、导师与资源

拿一篇本组硕士参与的论文，找一位在读生问十几分钟。最值得问的是，他入组后独立做成了表里的哪一行、第一次失败是谁和他一起查的。找人、核本届名额和问实习审批的具体做法，在择校篇。 [怎样找到在读生和毕业生](../实用篇/选学校和导师前怎么问.md#先找三类人各问一件对方亲手办过的事) · [问清实习是怎么批的](../实用篇/选学校和导师前怎么问.md#老师说实习可以先问上一个人怎么出去的)

### 4. 拿着导师的一张实验表去问学生

先挑组里近两三年一篇你真想做的论文。摘要扫一遍，把时间留给实验表和贡献说明。数据从哪里拿，哪条基线最难跑，什么环节由合作方完成？你知道得越具体，越容易分清自己进组后能接触到哪一段。

然后分别问一位在读生和一位毕业生。可以问「上次结果不理想，谁和你一起找原因？」「你进组到第一张表隔了几个星期？」「论文没赶上投稿那次，学院认可的毕业成果是什么？」两人的答案有出入，把课题、届别和项目负担记下来。实际名额和双选时间再去问学院。看一篇论文、聊两次，通常已经能发现最该继续问的是指导、算力，还是毕业。 [教育部导师指导行为准则](https://www.moe.gov.cn/srcsite/A22/s7065/202011/t20201111_499442.html)

### 5. 问清下周能分到的算力，再排下学期

- **成本** 和资源管理员聊半小时，再用最小配置做一次试跑。记下等待、训练、验证、峰值显存与费用。
- **说人话** 「有卡」只说明设备在那。请组里的同学按上一次真实作业说一遍，谁批、等了多久、最长能连续跑几小时、中断后怎么续、日志能留几天。再问课题组能否报销外部接口，自己是否有账单或额度记录可查。
- **收益** 能排出一周内跑得完的实验。示例里一次完整训练测得要两小时，两组各跑三次就要十二小时，还要算验证、重试和排队。如果分到的时段每次只有一小时，你还得先解决续跑。
- **证据等级** B，下列技术文档支持推理压测口径。C，训练两小时和合计十二小时是排期示例，用自己的资源规则和训练日志替换。
- **来源** [vLLM 服务压测文档](https://docs.vllm.ai/en/latest/cli/bench/serve/) · [MLPerf 推理基准与规则](https://github.com/mlcommons/inference)
- **备注** 把平常能预约的时段用作主实验预算。若预算只够跑一次，先缩数据、模型或题目范围，把剩余时段留给对照和复跑。

#### 大组设备多，小组能排到你，怎么选

假设你读两年制硕士，打算研一结束的暑假去实习，课题是比较两种数据清洗方法。大组有更多设备，导师也有相关论文。小组只有一台共享机器，但每周有固定时段，师兄能陪你跑第一次。只要那台机器装得下任务，能在下一次组会前把两个条件跑全，结果异常时还排得上复跑，我会先选小组。这类实验要反复查错，一周的排队时间会推迟下一轮调整。

如果大组已经有训练脚本、合规数据和专人排故，入门可能更快。给两边看同一页实验计划，问新生账号能用哪个队列、第一次失败找谁、正常教学周还有没有时间重跑。若大组能拿最近一名同方向硕士的作业说明他如何拿到数据、做完对照，我会重新比较两边。小组若只能跑一次，大组却能给出可复跑的时段和指导，我会改选大组。研究多机调度时，能否同时拿到多个节点也会直接改选题。

拿不到试用账号时，可以先请在读生按一份旧作业记录讲一遍。北京大学校级平台的公开文档可以用来练习怎么查，里面分别讲账号可用的计算分区、各队列的优先级和收费、作业最长运行时间。把这些问题带回目标组，问清你实际能用的队列和限制。 [北京大学高性能计算校级平台文档](https://hpc.pku.edu.cn/ug/guide/slurm/sbatch/) · [Slurm 的队列优先级与资源限制](https://slurm.schedmd.com/qos.html)

### 6. 拿到样本和许可，再答应做这个题

一种常见情形是合作项目有现成数据，对方却只能让学生在特定机器上使用，公开展示也要另外审批。开题以前，先问有没有合法可用的版本、能否在论文里放示例、盲审时怎么提交、以后能否为求职重建一份公开演示。个人设备、外部 API、权重、适配器和输出示例分别核对适用要求。需要单位伦理或数据管理流程的材料，先走相应流程并问清谁审批。

最省事的一次核验是拿一小批样本跑通，从原始材料、样本编号到标签都能追到来处。记上版本，写清缺失项怎么填和谁有权使用。靠企业项目毕业的读者可以在同一周准备一个公开、任务相近的小集，先确认评测脚本也能跑通。这样许可没下来时，还有一项成果可以继续。 [Datasheets for Datasets 原论文](https://arxiv.org/abs/1803.09010) · [FineWeb 数据处理与发布](https://arxiv.org/abs/2406.17557)

### 7. 把选组时听到的话放进同一页

| 事项 | 需要得到的回答 |
| --- | --- |
| 算力 | 这两周以及忙季各能分到多少机时，能不能在中断后续跑，配额不足时用什么替代 |
| 数据与产出 | 第一批能用的样本什么时候到，能否留版本和错误样例，团队成果里哪部分可以独立写进学位材料 |
| 带教与转向 | 第一次运行失败找谁看日志。合作方收回数据、项目到期或导师变动时，谁能确认备用题 |

把这三行补进通用核对表，其他栏用来放指导频率、毕业、横向分工、署名和实习等答复。每条末尾写谁在什么时候确认的。两个组都能去时，先找一项真会改变决定的条件，例如能否在实习前排完必须本人在场的实验。 [学校与导师核对表](../高性价比读研指南.md#学校与导师核对表)

## 三、做一个硕士能收尾的实验

今晚只做一轮基线，把输入、结果和一次失败记在一起。先写清要比较哪个变化，再按手里的数据和算力挑下面一个方案。还没跑通的时候继续往方案里堆模型，常常只会让下次更难知道错在哪里。用一个主指标决定方向，另留一两个帮助解释的指标。下面三个方案都可进一步缩减，实际计算开销用自己的机器测一次再算。

### 实验一｜拆开检索遗漏、噪声和生成错误

**问题。** 在一套许可明确、带版本号的开源工具文档中，固定生成模型，关键词检索、向量检索和重排分别能把哪些带引证的答案做得更可靠？

**数据。** 固定文档快照，按产品模块或文档族划分开发和测试。多个版本沿用同一说明或同一问题改写时放在同一组，保留一批版本迁移题作为单独测试切片，避免旧版本近重复内容进入开发集。每道题标出支持段落和适用版本，包括找不到证据的题。问题可以由人工写，也可以让工具起草后人工对原文。若测试的是生产中同一知识库，测试问题的证据文档可进入索引，测试问题和答案需冻结并且不参与调参。若研究迁移，另设新模块或新版本的切片，说明索引里什么时候可见这些文档。

**基线和对照。** 设无检索、BM25、密集检索、混合检索不重排、同一混合候选集加重排，以及人工给定证据的诊断组。固定生成模型、提示、证据数量与上下文预算。比较重排效果时，只在同一候选集上切换重排。人工证据组能帮助区分检索没找到与生成用错证据。

**测量。** 报告证据召回率 Recall@k 和答案正确率，另记引文是否真正支撑结论、无答案样本会不会误答，以及请求延迟。对同一批问题看配对差异，给结果分桶并列失败样例。若随机抽取部分让第二人复核，保留分歧和解决规则。正文已进入模型预训练的可能性无法排除时，报告无检索基线和局限。较长上下文里的证据顺序可以成为独立控制变量。 [BEIR 评测论文](https://arxiv.org/abs/2104.08663) · [Lost in the Middle 原论文](https://arxiv.org/abs/2307.03172)

**预算与复用。** 先估每题推理费用和人工复核时间，再扩大题集。比如无检索组和混合检索组都答错，而人工给证据就答对，你就有理由先修检索。若人工给证据仍引用错版本，就往提示、日期或生成这边查。把这样的题连同对照表装进作品，读的人能直接看到你是怎么定位到问题的。

#### 做一个成熟的 RAG 系统，还是去改模型

如果你手里只有可公开的产品手册和一小段算力，还想把成果拿去投应用岗，我会先做上面的检索实验。把「新版已经取消、旧版仍有」的功能做成一组题。先比较有无版本过滤，之后固定过滤规则，在相同候选集上测重排。如果证据一到，引用旧版的错误就减少，原来能答的题也照样答得出来，再拿一套没参与调参的手册确认。结果一致，就沿着检索和版本管理做下去。论文里可以讲清一种失败何时出现、哪一层干预能修好。面试里可以拿查询和证据演示给人看。

如果你的目标是做方法研究，光接通一套常见组件，研究贡献确实有限。假如正确片段和明确版本都交给模型之后，两套独立文档里的同类错误仍反复出现，人工也确认题意清楚，我就会做一轮小规模微调。先把显式版本规则和简短提示跑到位，再用同一个基础模型、相同证据和预先留出的文档族比较。若改完只让开发集变好，或让更多可答题被拒答，就回到错误分析，缩小原来要证明的结论。

Self-RAG 可以拿来对照。它要解决何时需要检索、拿到的片段值不值得用，因此作者训练模型学习按需检索与检视证据。读完可以问自己：「我手上的错误，也需要模型学一个新的行为吗？那条最简单的规则试过会怎样？」 [Self-RAG 原论文](https://arxiv.org/abs/2310.11511)

### 实验二｜测过滤训练数据对结构化抽取的作用

**问题。** 选公开许可明确的规范或科研数据，做一个可核查的字段抽取任务。在同一个基础模型、相同训练预算下，过滤错标签和近重复样本带来的收益有多大？

**数据。** 定义输入、字段、缺失值和判定方式，冻结训练、开发和测试版本。按原始文档、机构或模板分组，近重复以及同一材料转写的样本进入同一组。另留一个按时间或模板切开的迁移测试集，避免用训练语料的同分布结果代替新来源表现。对训练做去重和标签质检，发布清理规则和每一步处理的数量。

**基线和对照。** 设规则抽取、原模型加固定提示、原模型加少量示例、随机抽取训练数据的 LoRA、质检抽取训练数据的 LoRA。固定适配层、训练配置、输出格式、匹配的有效训练 token 预算和评测提示。训练组用相近的计算预算及重复次数。若想比较样本量，独立设置数据规模对照。用基础模型是否已见旧语料作为局限，并报告相同算力下是否复现。

**测量。** 分开看字段精确率和召回率、整体格式合法率、空字段上的错误填充率、跨模板表现。做标签歧义和长文裁剪的错误分析。小类别不只给总平均，同时报告实际样本数。若有重复和波动，报告各随机种子结果或对配对样本给不确定性区间。

**预算与复用。** 先用少量训练样本测单轮时间、峰值显存和验证成本，把对照、复跑和失败重试放进同一预算。举个可能的结果，清洗后输出更容易过格式检查，碰到新来源却仍在空字段上编值。报告可以直接答「值得继续用什么数据、在哪些场景先保留规则检查」。交付时附清理脚本、数据说明与可公开的配置。适配器许可允许的话也一并归档。 [LoRA 原论文](https://arxiv.org/abs/2106.09685) · [QLoRA 原论文](https://arxiv.org/abs/2305.14314) · [HELM 原论文](https://arxiv.org/abs/2211.09110)

### 实验三｜同一模型下，批处理会拖慢哪些请求

**问题。** 同一模型和服务引擎，把固定的请求按不同批处理策略处理，在短请求和长请求混跑时，哪一组配置能在时延要求下接住更多请求？

**数据。** 选允许公开的请求样本，或用公开文本合成长度分布和到达间隔。备好用于调参的负载与最终测试的固定负载，两套各含短、长和混合请求。保留种子、到达时间序列、模型输入输出长度、并发和重试规则。重复相同压测，再比较不同设置在各次运行中的表现。

**基线和对照。** 先在同一引擎下固定模型权重、精度、tokenizer、解码设置、设备和服务配置。以默认批处理配置及低并发或近串行配置为基线，一次改变批大小或调度相关设置。端到端测试明确客户端到服务端的计时起止。若另外测量化，把量化作为独立对照，评测其在若干关键任务上的输出质量变化。

**测量。** 同时报告首 token 延迟、输出 token 间隔、端到端延迟及其高分位、每秒完成的请求或 token、超时和错误率、显存峰值。固定预热规则和持续时间，分别测不同到达速率。关注满足自己服务阈值的有效吞吐，不能用仅由成功请求得到的平均数代表满载表现。

**预算与复用。** 找一段少受共享作业干扰的时间，记录设备、软件、驱动和种子，保存画图用的原始日志。假如吞吐上去了，最慢的那一批短请求却开始超时，回头看它们到达时有没有和长请求挤在一起。这类结果能帮助你在论文和面试中说清一种调度策略适用于什么流量。 [vLLM 论文](https://arxiv.org/abs/2309.06180) · [vLLM 服务压测文档](https://docs.vllm.ai/en/latest/cli/bench/serve/) · [MLPerf 推理基准](https://github.com/mlcommons/inference)

### 8. 先调换答案顺序，看裁判会不会改口

- **成本** 抽一批有难有易的答案，邀请同学按同一份规则独立打分。让模型裁判分别按 A、B 和 B、A 的顺序评一次。
- **说人话** 如果两种顺序给出相反结论，先把这些样本拿回人工桌上。看裁判是在奖篇幅和格式，还是在看引文能不能支持答案。开放题写清怎么算错，结构化任务可先让规则字段检查接手。
- **收益** 有依据判断评测分数值不值得信。人和模型在哪类问题上分歧最大，也能成为论文的错误分析。
- **证据等级** B。模型裁判对位置、冗长程度等因素的偏差已有实证，幅度随模型与题集变。
- **来源** [MT-Bench 裁判研究](https://arxiv.org/abs/2306.05685) · [lm-evaluation-harness 维护仓库](https://github.com/EleutherAI/lm-evaluation-harness) · [HELM 原论文](https://arxiv.org/abs/2211.09110)
- **备注** 记录裁判模型与配置、打分规则和拒答判定。某一语种或题型一致率偏低时，单独给出该组结果和人工判断。

## 四、按阶段推进并预设转向

组里的排期先记两种空档。一种是真能到岗的整天，一种是能连续跑训练或做现场验证的时段。两种经常撞在一起。实验做到哪一步才可暂停、离岗后谁能复跑，和到岗日期一起谈。

### 研一想找实习，先拿课表核一条真实岗位

花一刻钟用一条真实岗位核课表。小红书一条 Agent 产品研发实习写每周至少四天、至少三个月，另一条偏算法的实习要求相关专业在读硕士及以上、熟悉后训练等方法。先看自己差的是到岗时间，还是已经做过的工作。核完前者，带一张训练或评测排期去找导师和培养办，问「哪一轮实验交完就能去，开题或评审哪天必须回来？」若时间还是对不上，先换批次、城市或职位。 [小红书 Agent 产品研发实习样本](https://job.xiaohongshu.com/campus/intern/position/20736) · [小红书岗位样本 19568](https://job.xiaohongshu.com/campus/intern/position/19568)

收到面试，拿一个你实际动过的项目练一遍。给同学半小时，请他只追三个问题。你自己改了哪一段？改之前是怎么坏的？怎么判断改动没有把另一类用户的问题变得更糟？很多教程能帮你跑出界面，答这三个问题要靠自己的日志和对照。只有公开文档和普通电脑时，可以专测一类失败样本，比如引用指向旧版。想投推理岗就另外跑出一张可复现的延迟图，记下测试时的设备、负载和最慢的一批。企业实习拿不到，也能用公开材料先把这一轮做完。

**开源项目跑通了，中厂面试还是卡在工程细节。** 一位传统工科硕士在牛客写了 2025 年研一下的时间线。三月开始跑部署、微调和检索项目，第一家初创面完没后续，后来面一家中厂，工程问题答不下来。四月他自述拒了一份偏调研的录用，接受另一家离学校约半小时的公司的实习录用。原帖写到接受，没有交代到岗后的任务和产出。这条经验适用于手里的项目大多跟着教程做的人。练完一次面试，就知道该回去补工程还是换一批贴近自己经历的岗。只有理论或暂时出不去时，可以先从有明确问题、能自己验证的一段做起。 [研一下找第一份大模型实习的原帖](https://www.nowcoder.com/feed/main/detail/70c068d5d18b4cff857a0bd25081e0fb)

**也有人在实习里试出了愿意长期做的工作。** 港科大（广州）校访里，叶力维说自己在第二学年到特斯联做大模型应用，接触把自然语言问题转成 SQL 的任务。学校发访谈时，他已经在腾讯做人工智能工程师，负责的方向包括 ChatBI 和智能体平台。这个案例和上一位的区别，是他的项目本身安排了一年实习期。你只有暑期八到十周，就问能不能独立交付其中一段，例如收集并验证一组查询失败样本。等几个月权限才开放、或者首月没有带教的岗，对短期实习尤其不合适。 [港科大（广州）对叶力维的访谈](https://www.hkust-gz.edu.cn/zh/2025/11/21/%E6%AF%95%E4%B8%9A%E7%94%9F%E9%80%9A%E5%85%B3%E7%A7%98%E7%B1%8D-%E5%8F%B6%E5%8A%9B%E7%BB%B4%EF%BC%9A%E8%B7%A8%E7%95%8C%E6%8E%A2%E7%B4%A2%E8%80%85%E7%9A%84ai%E5%BE%81%E7%A8%8B/?variant=zh-cn)

真有两份实习能选，先问面试官「上一个实习生第一个月独立交了什么？我如果来，差不多会接哪一段，谁验收？」你是想试产品应用，就听有没有机会看真实失败和迭代反馈。你想做研究，偏调研的工作如果有技术带教、能做一轮有数据的比较，也可能值得去。通勤看每周实际往返几次，权限和保密则问是否有一份成果能在授权范围内展示。 [通用实习篇的审批做法](../实用篇/从研一开始准备实习.md#在导师那里把实习谈成一个能执行的计划) · [实习邀请只给四十八小时](../实用篇/从研一开始准备实习.md#邀请只给四十八小时审批还没走完)

### 9. 先完成一轮对照，再设扩大实验的条件

**入学前与第一学期。** 复现一个简单基线，留存环境与结果。和导师确认指导节奏、毕业的硬条件，列出主任务和可退到的小任务。用小样确认数据、指标和算力，写一个能一周内检查的实验问题。

**开题前。** 交一份实验卡片，写明预期结论、数据拆分、基线、主指标、最小算力计划、什么结果会使你修改判断。把进展写成「已经证实」「还有替代解释」「下一步能判定什么」。先拿一张可重跑的表再决定要不要加模型。

**中期前。** 把主实验跑稳，补机制对照或误差切片，开始写方法和结果。精力紧张时先确保基线、数据独立性和估计的不确定性，再考虑扩大样本或发表。把课程、横向和实习的硬节点排进同一张日历。

**送审前。** 冻结论文每张表用的数据和模型版本，失效实验也留档。给完整复跑留一轮资源，并让同学照说明重跑一个关键结果。成果认定、导师签字和拿证用同一张毕业日历另核。 [读研通用指南](../高性价比读研指南.md) · [把送审、答辩和拿证分开算](../实用篇/在读安排与毕业兜底.md#把送审答辩和拿证分开算)

### 10. 发现这周还在绕原地，先把问题缩小

| 信号 | 可执行的调整 |
| --- | --- |
| 约定的日期仍拿不到数据许可 | 切到公开替代数据，保留问题和评测方法，明确能覆盖与无法覆盖的场景 |
| 每次运行都改数据或评价方式 | 固定一个可以审计的测试集和一档主指标，重做最简单的基线 |
| 配额无法支持对照或重复 | 缩小任务或模型，优先保住同一指标、对照、复现和失败分析 |
| 提升落在重复波动内 | 报告不确定性和错误分布，再决定验证具体机制或缩小结论 |
| 横向项目长期挤占主课题 | 与导师核定毕业交付物和排期，尽早确定组内项目的可用成果或可替代课题 |
| 系统或训练做得动但没有研究问题 | 先复盘最不稳定的一类错误，构造能区分两种解释的实验再扩规模 |

组选题最难喊停的时候，往往是每周都找到下一件要做的事。和导师约一个能看结果的日期，例如数据到没到、现有预算能不能跑完一组对照，或上周的结果能否重跑。到期只看约定的结果，再判断这份题要不要缩。把决定和新日期写进组会记录。如果要改开题题目或培养计划，先问研究生秘书哪一步需要重新办理。

## 五、准备毕业、就业与继续研究

先把秋招、送审和颁证日期按[毕业倒排表](../高性价比读研指南.md#培养与毕业倒排表)记清。用一个能公开的项目准备两份材料。论文解释对照和结论的边界，面试说你负责哪一段、哪次失败让你改了做法。

### 毕业找工作，用一周试两条相邻路线

比如你做过校园问答检索和后端实习。准备一页相同的项目事实，应用岗版本先讲证据错在哪、改了哪条策略，后端版本先讲接口、日志和故障处理。一周试投几份符合学历、城市和届别的岗位，分别记「有没有进筛选」「第一次卡在哪一问」。想做后训练或模型研究，可以按自己的经历把第二条路换成数据与评测，作品里留基线、对照和一次不符合预期的结果。有一条路没有任何能讲的经历，就先把时间用来补一项作品。投同一家之前，查能填几个志愿、方向锁不锁。小红书 2027 届平台岗样本写了投递后不能更换职位方向。遇到这种规则，把两个方向放到不同雇主去试，避免先投了兴趣较低的方向，把更想去的锁在外面。 [小红书校招岗位页的志愿规则](https://job.xiaohongshu.com/campus/position/22059?referer_code=1HFWERNHLB1B)

**错过秋招后同时投后端和 Agent，有好几份录用，也有三次首面没过。** 一位 2026 届软件硕士在牛客写道，他秋招没参加，二月底从春招开始投。手里有后端实习和 RAG 项目，总共投了 36 家，有的没消息，三次申请同一家大厂不同岗位都止于首面。他自述拿到数份录用，最后选了 Agent 开发方向，实际入职没有后续。能借的是把已有经历拆成两条可投的路，再用实际回复改投递。手上只有课程作业，或已经错过目标岗位认可的毕业届别时，先修作品或换批次。单靠多投同家公司也未必能改变相同的短板。 [软件硕士的春招原帖](https://www.nowcoder.com/discuss/869231276035760128)

**做过训推系统，投不同的系统岗也会卡在不同地方。** 一名计算机本硕在牛客更新求职进度，三段实习涉及算子、训练框架和分布式调度。按发帖时的状态，他拿到中兴训推相关岗的录用，在快手异构计算岗止于二面，豆包的岗位当时还在审批。他还提到一个编译器工具链岗位，了解工作方向后自己停了流程。你有相似工程经历，也得拆开看日常。想做服务延迟与稳定性，就问一周主要在定位线上服务问题、改框架，还是做算子和代码生成。有一个自己真想练的环节，再用对应的日志、对照和贡献说明来准备。 [系统岗求职进度原帖](https://ac.nowcoder.com/discuss/1730330?channel=-1&source_id=discuss_tag_discuss_hot_nctrack&type=0)

面试完当天只记一个卡住的问题和下一次怎么补。没进筛选时，先核岗位资格和简历首页有没有对应任务。进面后总被问住同一处，就回去做一次能解释的实测。已经到谈录用，拿十分钟问清团队、常驻地、主要任务和报到文件。有团队现在需要你做传统服务开发，后续才可能接模型。要是你非做模型研究才愿意去，就把这个问题放到回复之前问，别把意向中的调岗算成已确定。 [几种毕业去向与签约时间怎么比](../实用篇/考公考编与其他去向.md#二其他去向也要做一次真的验证)

### 11. 查明哪份材料算毕业，再碰投稿和实习时间

- **成本** 留半天，把你这一届的学分、成果认定、预答辩、送审和正式答辩节点记下来，找教学秘书确认存疑的要求。
- **说人话** 如果目标会议在学院材料截止后才放结果，先问是否认接收、在线发表或正式见刊，署名和第一单位怎样算。参与产学合作的同学，再问数据可否在盲审里呈现、目前谁有权批准。
- **收益** 拿论文、实习和校招一起排。例如实习要在暑假连续到岗，预留时间跑完主实验，约好改稿和回校的周期。
- **证据等级** A 级是适用于你的院校和届别的书面文件，倒排时间属于 C 级做法。
- **来源** [通用指南里的毕业倒排](../高性价比读研指南.md#三读研期间怎么做) · [东南大学信息科学与工程学院送审流程样本](https://radio.seu.edu.cn/_upload/article/files/4f/13/2f6d5c594ba497036f5a344ce27e/aec18e0d-bd97-4225-bc3d-0340301ede11.pdf)
- **备注** 学院允许以其他成果申请学位时，早点确认材料和最迟提交日期。实验结果和预期不同也可以写进论文，学校认可何种成果仍以书面要求为准。

### 12. 把最重要的一张表交给陌生同学重跑

挑论文里你最想给面试官看的那张表。让没接触过项目的同学只用你给的数据来源、版本、配置与运行说明重跑。看他在哪一步来问你。模型权重找不到、测试脚本默认指向开发集、画图用的是旧日志，这些错误往往比再调一个参数更值得先解决。旁边留一页简短说明，写清你做的部分、谁负责其他部分、什么时候需要人工复核。

毕业答辩用这张表解释结论的边界，找工作用同一套材料讲你如何定位问题，申请博士时可以从其中一类失败继续提出问题。若材料无法公开，先查清协议允许的披露范围，再用许可明确的公开小样准备可重建版。养成每次跑完就留配置和日志的习惯，交接时你只需补读者缺的信息。 [Datasheets for Datasets](https://arxiv.org/abs/1803.09010) · [lm-evaluation-harness 维护仓库](https://github.com/EleutherAI/lm-evaluation-harness)
